# Hostel Accommodation and Student Services Management System

College DBMS project for managing hostel accommodation and student services. It includes a Flask JSON API and a responsive administration dashboard built with HTML, CSS, and vanilla JavaScript. All operational dashboard data is read from MySQL through the Flask API.

## Features

- Student, hostel block, room, bed, allocation, and transfer management
- Fee schedules, payment history, visitor check-in/check-out, complaints, maintenance, and vacating records
- Occupancy, vacancy, fee dues, allocation history, visitor, complaint, and maintenance reports
- Database-enforced referential integrity and validation, including one active allocation per student and bed
- Transactional allocation, transfer, and vacating workflows
- Responsive dashboard with API-backed statistics, live tables, search, validation, and status indicators

## Technologies

- Python 3.10+ and Flask
- MySQL 8.0.16+ with InnoDB
- `mysql-connector-python` and `python-dotenv`
- HTML, CSS, and vanilla JavaScript

## Requirements

- MySQL 8.0.16 or newer (for enforced `CHECK` constraints, generated columns, and the included trigger behavior)
- Python 3.10+
- Packages in `requirements.txt`

## Initialize the database

From a MySQL client with permission to create a database, run:

```sh
mysql -u root -p < database/schema.sql
mysql -u root -p hostel_management < database/sample_data.sql
```

Alternatively, in MySQL Workbench, open and execute `database/schema.sql`, then `database/sample_data.sql`. The schema script drops and recreates the project's tables and views; do not run it against a database containing data you need.

If you already have the earlier initialized project database, preserve its data and apply `database/migrations/001_normalize_transfers.sql` once. It removes the redundant transfer student column; the student is derived through the source allocation. Do not run this one-time migration again after it succeeds.

The sample users intentionally have placeholder password hashes. Replace them with hashes generated by the application before enabling login; they are not usable credentials. No real secret is included.

Copy `.env.example` to `.env` in the project root and replace its placeholder values with your local MySQL connection settings. Keep `.env` private; it is excluded by `.gitignore`. `database.py` loads that file automatically without overriding environment variables already set by the shell or deployment environment. The database defaults to `hostel_management`. Install dependencies with `pip install -r requirements.txt`, then run `python app.py`.

Open `http://127.0.0.1:5000/` after starting the app to use the dashboard. It loads all operational data from the Flask API; dashboard statistics, tables, forms, and reports are backed by the configured MySQL database. The API is rooted at `/api`; `/api/health` checks database connectivity and `/api/stats` returns row counts. The frontend is served by Flask on the same origin, so CORS middleware is not needed.

## API overview

- `/api/health`, `/api/stats`
- `/api/students`, `/api/blocks`, `/api/rooms`, `/api/beds`
- `/api/allocations`, `/api/transfers`, `/api/fees`, `/api/payments`
- `/api/visitors`, `/api/complaints`, `/api/maintenance`, `/api/vacating`
- `/api/reports/occupancy`, `/api/reports/vacancies`, `/api/reports/fee-dues`, `/api/reports/allocation-history`, `/api/reports/visitors`, `/api/reports/complaints`, `/api/reports/maintenance`

The module routes support the read/create/update/delete operations defined by the Flask application. Write JSON request bodies using the field names shown in `app.py`; validation and database errors are returned as JSON with HTTP status codes.

## Model and integrity

The schema is normalized around users, students, blocks, rooms, beds, allocations, and independent service/finance records. Transfers reference source and destination allocations; student identity is derived from those allocations instead of being duplicated in the transfer row. Generated unique keys enforce at most one active allocation per student and per bed. Triggers enforce room bed/occupancy limits, block gender policy, fee payment caps, and vacating dates. Foreign keys use restrictive deletes for historical/financial facts and `SET NULL` for optional user associations.

`queries.sql` is an educational query catalog. Its INSERT/UPDATE/DELETE examples are intentionally mutating; run on a disposable copy if you want to preserve sample data.

## Tests

With MySQL running and `.env` configured, from this project directory run:

```sh
python -m unittest discover -s tests -v
```

The integration suite checks the configured database and API. Write tests use uniquely named temporary records and remove them in cleanup; transaction-failure tests verify that failed transfer and vacating operations leave the original allocation state unchanged. The suite skips when MySQL is unavailable.
